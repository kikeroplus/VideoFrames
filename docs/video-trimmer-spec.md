# 動画トリミング／切り抜きアプリ 仕様書

作成日: 2026-09-13
対象環境: Windows 11 / Python 3.11+
用途: ローカルの動画フォルダを開き、GUI上で「一部削除」と「一部抜き出し」を行う。

---

## 1. 目的とスコープ

### やること
- フォルダ内の動画をサムネイル一覧で俯瞰し、対象を選ぶ
- 選んだ動画から不要部分を **削除** する（機能1）
- 選んだ動画から必要部分を **抜き出す** （機能2）

### やらないこと（v1のスコープ外）
- 複数動画の連結、トランジション、テロップ、エフェクト
- 音声の編集（音量調整・BGM追加など）
- クラウド連携、動画のアップロード

---

## 2. 技術スタック

| 領域 | 採用 | 理由 |
|---|---|---|
| GUI | PySide6 (Qt6) | 既存プロジェクトと共通。QGraphicsView/QListViewでサムネ一覧が作りやすい |
| 動画処理 | ffmpeg / ffprobe (CLI を subprocess 実行) | 対応フォーマットが最も広い。進捗パースも容易 |
| プレビュー再生 | QMediaPlayer + QVideoWidget | 標準で完結。コマ送り精度が不足する場合のみ PyAV へ移行 |
| メタ情報取得 | ffprobe (`-print_format json`) | duration / fps / codec / 解像度をまとめて取得 |
| 設定保存 | QSettings（レジストリ or ini） | 最終フォルダ、出力先、精度モードを記憶 |

**ffmpeg の扱い:** 同梱せず、起動時に `PATH` および `./bin/ffmpeg.exe` を探索する。見つからない場合は設定ダイアログで実行ファイルのパスを手動指定させる。パスは QSettings に保存。

## 4. データモデル

```python
@dataclass
class VideoItem:
    path: Path
    duration: float          # 秒
    fps: float               # r_frame_rate を float 化
    width: int
    height: int
    vcodec: str
    acodec: str | None
    size_bytes: int
    thumb_path: Path | None  # キャッシュ済みサムネ
    keyframes: list[float] | None = None   # 遅延取得。§8参照

@dataclass
class EditJob:
    src: Path
    dst: Path
    mode: Literal["extract", "delete_head", "delete_tail", "delete_middle"]
    ranges: list[tuple[float, float]]  # 残す区間（秒）。deleteも「残す区間」に正規化してから処理
    strategy: Literal["copy", "encode"]   # 区間ごとではなくジョブ全体で統一する
    snapped: bool = False                 # スナップでIN点を動かしたか（ログ・結果表示用）
```

**重要な設計判断:** 削除も抽出も、内部的には「**残す区間のリスト**」に正規化してから ffmpeg に渡す。こうすると処理経路が1本化でき、途中削除（区間が2つ残る）も同じコードで扱える。

```
│ │   ││   │    │  ────────●──────────────── シークバー      │
│ └───┘└───┘    │  [◀◀][▶/❚❚][▶▶]  00:01:23.400 / 00:10:00 │
│ ┌───┐┌───┐    │  [◀コマ][コマ▶]  [IN設定][OUT設定]        │
│ │   ││   │    ├──────────────────────────────────────────┤
│ └───┘└───┘    │  タブ: [ 抜き出し ] [ 削除 ]              │
│               │  （各パネルの内容は §6, §7）              │
├───────────────┴──────────────────────────────────────────┤

└──────────────────────────────────────────────────────────┘
```

### 5.1 フォルダ選択
- `QFileDialog.getExistingDirectory` でフォルダ選択
- 対象拡張子: `.mp4 .mov .mkv .avi .wmv .m4v .ts .webm`（設定で変更可）
- サブフォルダは v1 では**走査しない**（チェックボックスで再帰オプションを用意しておくのは可）
- 起動時は前回のフォルダを自動で開く

### 5.2 サムネイル一覧
- `QListView` + `IconMode` + `QStandardItemModel`。サムネサイズは 160/240/320px を切替可能
- 各アイテム表示: サムネ画像 / ファイル名（省略表示）/ 長さ `mm:ss` / 解像度
- **生成タイミング:** フォルダを開いた直後に非同期で順次生成。UIは即座に空枠で表示し、できたものから差し替える
- **取得位置:** 先頭は真っ暗なことが多いため、`duration * 0.1` の位置（最低でも1秒地点）から1枚抽出
  ```
  ffmpeg -ss {pos} -i "{src}" -frames:v 1 -vf "scale=320:-2" -q:v 4 -y "{cache}"
  ```
- **キャッシュ:** `%LOCALAPPDATA%\VideoTrimmer\thumbs\{hash}.jpg`
  hash は `sha1(絶対パス + st_mtime + st_size)` の先頭16文字。ファイルが更新されれば自動で作り直される
- **並列度:** `QThreadPool` で最大4並列。フォルダを切り替えたら未処理タスクはキャンセル

### 5.3 プレビュー／シーク
- 動画選択でプレビューにロード（自動再生はしない）
- シークバーは秒ではなく **ミリ秒精度** で扱う
- キーボードショートカット:

| キー | 動作 |
|---|---|
| Space | 再生 / 一時停止 |
| ← / → | 1フレーム戻る / 進む |
| Shift + ← / → | 1秒 戻る / 進む |
| Ctrl + ← / → | 10秒 戻る / 進む |
| , / . | 前 / 次のキーフレームへジャンプ（§8） |
| I | 現在位置を IN点に設定 |
| O | 現在位置を OUT点に設定 |
| Enter | 実行（アクティブなタブの処理を開始） |

- 現在位置は `HH:MM:SS.mmm` と **フレーム番号** を併記表示する

## 6. 機能1: 一部削除

### UI（削除タブ）

```
削除モード:  ( ) 冒頭から   ( ) 末尾から   ( ) 途中を指定

  単位:  (•) 秒   ( ) フレーム
  長さ:  [  5.0  ] 秒         ← 冒頭/末尾のとき

  開始:  [00:01:23.400] [現在位置を取得]   ← 途中のとき
  終了:  [00:01:45.000] [現在位置を取得]

  結果: 10:00.000 → 09:38.600（-21.4秒 / 残り区間 2つ）
  （カット方式の選択とキーフレーム判定の表示は §8.4 の共通UI）

  [ 削除を実行 ]
```

### 動作定義

| モード | 残す区間 |
|---|---|
| 冒頭からN | `[(N, duration)]` |
| 末尾からN | `[(0, duration - N)]` |
| 途中 A〜B | `[(0, A), (B, duration)]` |

- **フレーム単位指定:** `秒 = フレーム数 / fps`。VFR（可変フレームレート）の動画では誤差が出るため、ffprobe で VFR を検出したら「フレーム指定は概算になります」と警告を1度だけ表示する
- **入力バリデーション:** N ≦ 0、N ≧ duration、A ≧ B、区間が動画長を超える、といったケースは実行ボタンを無効化し、理由をラベルに表示する
- **冒頭削除・末尾削除:** 残す区間が1つなので単純なトリム。特に**末尾削除は常にストリームコピーで処理できる**（§8.3）
- **途中削除の実装:** 残す区間をそれぞれ一時ファイルに切り出し → concat demuxer で結合 → 一時ファイル削除。切り出しをコピーで行うか再エンコードで行うかは §8 の判定に従い、**2区間で方式を混在させない**（混在すると結合できない）
- 結合の前提として、全区間が同一コーデック・同一解像度・同一fpsであること（同一ソースなので基本は満たされる）

## 8. カット方式の自動判定（最重要の設計ポイント）

**方針: 再エンコードせずに済むケースを自動で検出し、その場合は必ずストリームコピーを使う。** 再エンコードは「やむを得ない場合のみ」の手段として扱う。

### 8.1 なぜ判定が必要か

ストリームコピー（`-c copy`）は再圧縮せず、元の画質のまま一瞬で終わる（1時間の動画でも数秒）。ただし **カットの開始点はキーフレーム上にしか置けない**。キーフレーム以外の位置を開始点に指定すると、ffmpeg は手前のキーフレームから出力するか、または冒頭が数フレーム崩れる・静止する。

逆に言えば、**開始点がキーフレームに一致していればコピーで完全に正しく処理できる**。終了点は任意のフレームで問題ない（詳細は §8.5）。

### 8.2 キーフレーム位置の取得

パケットヘッダのみを読むため、デコードせずに済み高速（1時間のH.264で概ね2〜10秒）。

```
ffprobe -v error -select_streams v:0 -show_packets \
        -show_entries packet=pts_time,flags -of csv=p=0 "{src}"
```

- 出力の2列目に `K` を含む行がキーフレーム。1列目の `pts_time` を float で集めて昇順リストにする
- **取得タイミング:** フォルダを開いた時点では取らない。**動画が選択された時にバックグラウンドで1回**取得する。取得中もUIは操作可能とし、完了までは「判定中…」を表示
- **キャッシュ:** `%LOCALAPPDATA%\VideoTrimmer\keyframes\{hash}.json`（hash の作り方はサムネと同じ）。2回目以降は即座に読み込む
- 取得に失敗した動画は「判定不能」として扱い、安全側（再エンコード）に倒す

### 8.3 判定ロジック

各モードで「コピー可能か」は開始点だけで決まる。

| モード | 開始点 | コピー可否 |
|---|---|---|
| 末尾からN秒削除 | 0（常にキーフレーム） | **常にコピー可** |
| 冒頭からN秒削除 | N | N がキーフレーム上なら可 |
| 抜き出し | IN | IN がキーフレーム上なら可 |
| 途中A〜B削除 | 前半=0 / 後半=B | B がキーフレーム上なら可 |

```python
def can_copy(t: float, keyframes: list[float], fps: float) -> bool:
    """t がキーフレーム位置と一致するか（許容差=1フレーム時間の半分）"""
    tol = 0.5 / fps
    i = bisect_left(keyframes, t - tol)
    return i < len(keyframes) and abs(keyframes[i] - t) <= tol
```

これに加え、以下のいずれかに該当する場合はキーフレーム上でも再エンコードする。

- キーフレーム情報が取得できなかった
- 映像コーデックが出力コンテナに格納できない（同一拡張子で出力する限り通常は発生しない）
- ユーザーが「常に再エンコード」を選んでいる

### 8.4 UI（3つのタブ共通の下部に配置）

チェックボックスではなく3択にする。既定は「自動」。

```
カット方式:  (•) 自動   ( ) コピー優先   ( ) 常に再エンコード

┌────────────────────────────────────────────────┐
│ ✅ 再エンコードなしで処理できます（推定 3秒）    │   ← 開始点がキーフレーム上
└────────────────────────────────────────────────┘
┌────────────────────────────────────────────────┐
│ ⚠ 開始点がキーフレーム上にありません            │   ← 一致しない場合
│   最寄り: -0.35秒 (00:02:09.650) / +1.28秒     │
│   [ ← 手前に合わせる ] [ 奥に合わせる → ]       │
│   このまま実行すると再エンコードします（推定 4分）│
└────────────────────────────────────────────────┘
```

- **自動:** 判定に従いコピーまたは再エンコード。位置がずれている場合は上記のように最寄りキーフレームを提示し、ワンクリックでスナップできるようにする（押せばコピーに切り替わり、表示も更新される）
- **コピー優先:** 開始点を自動的に最寄りのキーフレームへスナップし、常にコピーで処理する。実際に使われた位置は完了後に結果として表示する
- **常に再エンコード:** 判定を無視して §8.6 の設定で再エンコード

さらに **シークバー上にキーフレーム位置を細い縦線で描画** する。`,` / `.` キーで前後のキーフレームへジャンプできるので、最初からキーフレーム上で IN 点を決めれば常にコピー処理になる。これが最も効く導線なので Phase 3 で必ず入れること。

スナップ方向の既定は「手前（前のキーフレーム）」。抜き出しでは欲しい部分が削れないほうが安全なため。

### 8.5 コピー時のコマンド

```
# 抜き出し・冒頭削除（-ss と -to を両方 -i の前に置く。
#  こうすると -to は入力タイムライン上の絶対位置として解釈される。
#  -to を -i の後ろに置くと「出力の長さ」になり意味が変わるので注意）
ffmpeg -ss {start} -to {end} -i "{src}" -c copy -avoid_negative_ts make_zero -y "{dst}"

# 末尾削除（開始0なので常にコピー可）
ffmpeg -i "{src}" -t {keep_dur} -c copy -avoid_negative_ts make_zero -y "{dst}"

# 途中削除: 2区間をコピーで切り出し → concat demuxer で結合（結合側も -c copy）
ffmpeg -f concat -safe 0 -i "{list.txt}" -c copy -y "{dst}"
```

**既知の制約（仕様として許容し、実装者は取り繕わないこと）:**
- 終了点は任意位置で切れるが、末尾数フレームが後続フレームを参照している場合（Bフレーム／オープンGOP）、最後の一瞬に軽微な乱れが出ることがある
- 音声はフレーム境界が映像と一致しないため、開始位置で最大数十msのずれが生じうる。通常は知覚できない
- 途中削除の結合点では、前半の末尾が上記の理由で一瞬乱れることがある。気になる場合は「常に再エンコード」を選ぶ

### 8.6 再エンコード時の設定

```
ffmpeg -ss {start} -to {end} -i "{src}" \
       -c:v libx264 -crf 18 -preset medium -c:a aac -b:a 192k \
       -avoid_negative_ts make_zero -y "{dst}"
```

元動画が HEVC の場合は `libx265 -crf 23` に切り替える（ffprobe の `vcodec` で分岐）。音声トラックが無い場合は `-an`。

### 8.7 将来の拡張（v1では実装しない）

先頭の部分GOPだけ再エンコードし、残りをコピーして結合する「スマートカット」。任意の位置で正確かつ高速に切れるが、結合時のタイムスタンプ処理が難しい。v1 では §8.4 のスナップ導線で十分実用になるため扱わない。

## 9. 出力ルール

- **元ファイルは絶対に上書き・削除しない**（これは厳守。実行前に `dst != src` をアサート）
- 既定の出力先: 元フォルダ直下の `output/`（設定で任意フォルダに変更可）
- 命名規則:
  - 抜き出し: `{元名}_clip_{通番3桁}{元拡張子}` 例 `PXL_20260101_clip_001.mp4`
  - 削除: `{元名}_cut_{通番3桁}{元拡張子}`
  - 通番は既存ファイルを走査して未使用の番号を採る（既存を上書きしない）
- コンテナは原則として元と同じ拡張子を維持する
- 完了後にトースト通知を出し、「フォルダを開く」ボタンから `explorer /select,` で該当ファイルを選択表示する

## 10. 非同期処理と進捗

- ffmpeg は必ず別スレッド（`QRunnable` / `QThread`）で実行し、UIをブロックしない
- 進捗は `-progress pipe:1 -nostats` の出力から `out_time_ms=` を拾い、`out_time_ms / (総処理秒 * 1e6)` で算出
- 途中削除は「区間切り出し n個 + 結合1個」の複数ステップになるため、全体進捗は工程数で按分する
- キャンセルボタン: プロセスに `terminate()` → 3秒待って `kill()`。生成途中の一時ファイルと出力ファイルは必ず削除する
- 一時ファイルは `tempfile.TemporaryDirectory()` 配下に置き、例外時も `finally` で確実に片付ける
- 処理中はサムネ一覧・タブ操作を無効化（誤操作防止）

## 11. エラー処理

| ケース | 挙動 |
|---|---|
| ffmpeg/ffprobe が見つからない | 起動時にダイアログで通知し、パス指定を促す。指定まで編集機能は無効 |
| 破損／未対応ファイル | 一覧には「読み込み不可」アイコンで表示し、選択しても編集不可。一覧全体は落とさない |
| 音声トラックなし | `-c:a` 系オプションを付けずに実行する（ffprobe の結果で分岐） |
| 出力先に書き込めない | 実行前にチェックし、理由付きで中断 |
| ffmpeg が非ゼロ終了 | stderr の末尾20行をダイアログに表示し、ログを `%LOCALAPPDATA%\VideoTrimmer\logs\` に保存 |

## 12. 実装フェーズ（この順で作る）

各フェーズの終わりに必ず動作確認 → `git status` → `git diff` → コミットする。

- **Phase 0 — 土台**
  リポジトリ初期化、`requirements.txt`、ffmpeg/ffprobe 検出、`probe.py`（ffprobeでメタ取得）、`timecode.py` とそのユニットテスト。GUIはまだ作らない。CLIで1本のmp4のメタ情報が出力できればOK。

- **Phase 1 — 一覧UI**
  メインウィンドウ、フォルダ選択、サムネ非同期生成＋キャッシュ、一覧表示。選択で右ペインにファイル情報が出るところまで。

- **Phase 2 — プレビュー**
  QMediaPlayer 統合、再生/一時停止/シーク、コマ送り、現在位置のタイムコード＋フレーム番号表示、ショートカット。

- **Phase 2.5 — キーフレーム解析**

  削除タブ、3モード、フレーム単位入力、「残す区間」への正規化、途中削除の分割＋concat結合。

- **Phase 5 — 仕上げ**

## 14. 未決定事項（実装前に決めたいこと）

1. **プレビューのコマ送り精度** — QMediaPlayer は環境によって1フレーム単位のシークが不正確。ズレが気になる場合は PyAV でデコードして QImage 表示に切り替える（実装コストは上がる）。Phase 2 で実機確認してから判断する。
2. **再エンコード設定** — `libx264 / CRF18 / preset medium` を既定としたが、元動画が HEVC や高ビットレートの場合は設定で変更したくなる可能性がある。v1 では固定でよいか。
2b. **スナップの既定方向** — 「手前のキーフレーム」を既定としたが、冒頭削除では手前にスナップすると消したい部分が少し残る。モードごとに既定を変えるべきか（削除は奥、抜き出しは手前、など）。実際に何本か処理してから決めてよい。
3. **複数選択の一括処理** — 「全動画の冒頭5秒を削除」のようなバッチ処理を将来的に使うか。使うなら Phase 1 の一覧を最初から複数選択対応にしておくほうが安い。
4. **GPUエンコード（NVENC / QSV）** — 長尺の再エンコードが遅い場合に効く。利用可否の自動判定込みで v2 の候補。
